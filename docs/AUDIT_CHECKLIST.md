# Самопроверка по критериям курса

Таблица составлена по переносимым критериям из аудитов проектов курса
(Cycloid, CarCollisionSimulator, CartCollision, lab1 «преломление»,
oberbek-rotation). Для каждого замечания указано, где и как оно закрыто
в этом проекте, и чем это можно показать на защите.

Обозначения: ✅ выполнено и проверяется автоматически · ☑️ выполнено,
проверяется вручную · ⚠️ требует действий команды вне кода.

## 1. Воспроизводимость и сборка

| Замечание из аудитов | Статус | Где / как показать |
|---|---|---|
| Нет файлов проекта, нельзя собрать после clone (Cycloid) | ✅ | `requirements.txt`, `pyproject.toml`; шаги в README; job `tests` в CI на Linux и macOS |
| Сборка привязана к ОС (WPF/WinForms не собирается на macOS) | ✅ | чистый Python + браузер; CI на `ubuntu-latest` и `macos-latest`, Python 3.10 и 3.13 |
| Машинно-зависимые пути, generated-файлы в репозитории (oberbek) | ✅ | пути только относительные; `.gitignore` исключает venv, кэш, личные настройки IDE |
| Приложение не запускается из чистого clone (oberbek, CarCollision) | ✅ | job `smoke` в CI запускает `run.py` и обращается к API; конфигурации PyCharm в `.idea/runConfigurations` |
| Нет инструкции запуска | ✅ | README: PyCharm (macOS) и терминал, таблица частых проблем |

## 3. Архитектура и MVVM

| Замечание | Статус | Где / как показать |
|---|---|---|
| Core зависит от UI | ✅ | `lj_md/core` не импортирует ничего из `viewmodel`/`view` |
| ViewModel зависит от UI-фреймворка (Avalonia) (lab1) | ✅ | ViewModel — чистый Python, без Flask; тестируется без сервера |
| Событие ViewModel без подписчика (lab1) | ✅ | подписчик — журнал событий сервера (`ViewModelRegistry._create`), тест `test_phase_changes_are_logged` |
| Дублирование DTO между слоями, contract drift (lab1) | ✅ | один источник — `state()`; контракт в `docs/API.md`, `assert_state_contract` в тестах |
| Клиентская и серверная валидация расходятся (lab1) | ✅ | форма строится по схеме ViewModel; тест `test_schema_matches_viewmodel_validation` |
| Длительный расчёт блокирует UI, нет отмены (oberbek) | ✅ | расчёт идёт кадрами (`tick`), бюджет `PAIR_STEP_BUDGET / N²` шагов за кадр; «Пауза» в любой момент |
| Явные состояния Idle/Running/Completed/Failed (oberbek) | ✅ | `Phase`: idle, running, paused, completed, failed — в интерфейсе и экспорте |

## 4. Физическая модель и численный метод

| Замечание | Статус | Где / как показать |
|---|---|---|
| Модель описана, но не обоснована / есть ограничения (oberbek) | ✅ | `docs/THEORY.md` + панель «Ограничения модели» в интерфейсе |
| Нет контроля погрешности, h и h/2 (lab1, oberbek) | ✅ | порядок сходимости при dt, dt/2, dt/4, dt/8 = **2.00** (`docs/VERIFICATION.md` §3) |
| Нет сравнения с аналитикой (lab1, oberbek) | ✅ | период колебаний молекулы и точка поворота — ошибка < 10⁻³ и < 10⁻⁶ |
| NaN/Infinity не блокируются (lab1) | ✅ | проверка конечности на каждом шаге + отказ от `nan`/`inf` во вводе; строгий JSON (тест `test_state_is_strict_json`) |
| Недопустимые входные данные допускаются (lab1) | ✅ | `SimulationParameters.validate()` (в т. ч. r<sub>c</sub> ≤ L/2), 10 параметризованных тестов плохого ввода |
| При ошибке расчёта результат теряется (lab1) | ✅ | откат к последнему устойчивому состоянию; данные до сбоя видны и экспортируются |
| Лимит шагов «молча» считается успехом, нет причины завершения (lab1) | ✅ | `t_max` + `termination.reason` (`t_max_reached`, `numerical_instability`, …) в CSV/JSON |
| Последний шаг до границы теряется (lab1) | ✅ | ровно ⌈t<sub>max</sub>/dt⌉ шагов, последнее состояние всегда в истории (тест `test_t_max_stops_exactly…`) |
| Статистика по округлённым данным (lab1) | ✅ | расчёты в float64; округление только в `state()`; CSV в полной точности |
| Величины в неверных единицах / без единиц (lab1) | ✅ | единицы в подписях полей, плиток, осей и столбцов CSV; пересчёт в аргон (K, пс, МПа) |

## 9. Командный процесс

| Замечание | Статус | Что сделать |
|---|---|---|
| Нет CI (все проекты) | ✅ | `.github/workflows/ci.yml`: lint, tests (2 ОС × 2 версии Python), smoke, e2e, verification |
| Нет Definition of Done | ✅ | `CONTRIBUTING.md`, шаблон PR `.github/pull_request_template.md` |
| Не определены ответственные за код | ✅ | `docs/ROLES.md`, `.github/CODEOWNERS` (подставить логины участников) |
| Финальная версия не в `main` (lab1) | ⚠️ | открыть PR `qa → main` и слить после review |
| Нет review в PR, PR слит за секунды (lab1) | ⚠️ | дальнейшие изменения — через PR с review участника другой роли |
| `main`/`development` не защищены | ⚠️ | GitHub → Settings → Branches: обязательный PR, approve, зелёный CI |
| В contributors меньше участников, чем в команде (все проекты) | ⚠️ | каждый участник вносит и ревьюит изменения в своей зоне со своего аккаунта |
