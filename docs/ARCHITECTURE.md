# Архитектура: MVVM

```
┌──────────────────────── Браузер ───────────────────────┐
│  VIEW (клиент)  index.html + app.js / scene.js / charts │
│   data-bind="display.temperature"   → текст            │
│   data-command="start"              → кнопка           │
│   форма строится по схеме полей из ViewModel           │
└───────────────▲──────────────────────────┬─────────────┘
                │ JSON state() (docs/API.md)│ команды / параметры (HTTP)
┌───────────────┴──────────────────────────▼─────────────┐
│  VIEW (сервер)  view/app.py — Flask, без логики,        │
│                 коды ошибок, лимиты, журнал событий     │
├────────────────────────────────────────────────────────┤
│  VIEWMODEL  viewmodel/simulation_vm.py                  │
│   • фаза: idle → running ⇄ paused → completed | failed  │
│   • команды: start, pause, step, reset (+ can_execute)  │
│   • update_parameters / apply_preset / load_experiment  │
│   • state(): строки для показа, ряды для графиков       │
│   • export_csv / export_json с метаданными              │
├────────────────────────────────────────────────────────┤
│  MODEL  core/                                           │
│   Simulation → ParticleSystem, VelocityVerlet,          │
│                Thermostat, LennardJones, observables,   │
│                units (пересчёт в аргон)                 │
└────────────────────────────────────────────────────────┘
```

Зависимости направлены строго вниз: `view → viewmodel → core`.
Ядро не импортирует ничего из верхних слоёв, ViewModel не импортирует Flask.
Единственная точка сборки (composition root) — `create_app()` в `view/app.py`;
заглушек, демо-данных и второй реализации физики в проекте нет.

## Model (`lj_md/core`)

Чистая физика на NumPy. Точка входа для верхних слоёв —
`Simulation(SimulationParameters)`:

| Метод / свойство | Что делает |
|---|---|
| `step(n, record_every)` | n шагов Верле + термостат, запись истории; не выходит за `t_max` |
| `snapshot()` | мгновенные E<sub>kin</sub>, E<sub>pot</sub>, E, T, P |
| `history` | кольцевой буфер `Snapshot` (до 2000 точек, последняя точка всегда записана) |
| `completed` | достигнута длительность `t_max` |
| `wall_pressure()` | давление по импульсу, переданному стенкам (независимо от вириала) |
| `set_thermostat(...)` | смена термостата без перезапуска |
| `SimulationParameters.validate()` | физическая согласованность (например, r<sub>c</sub> ≤ L/2 при PBC) |

**Устойчивость.** После каждого шага проверяются конечность координат,
скоростей, энергии, вириала и смещение атома за шаг (< σ/2). При нарушении
система **откатывается к последнему устойчивому состоянию** и выбрасывается
`SimulationError` с номером шага — история и координаты до сбоя остаются
корректными и доступны для экспорта. Ядро не решает, как сообщить об этом
пользователю.

Внутренние расчёты — в полной точности `float64`; округление выполняется
только в ViewModel для показа.

## ViewModel (`lj_md/viewmodel`)

- `ObservableProperty` и `Observable.subscribe` — уведомления об изменениях
  (аналог `INotifyPropertyChanged`). Подписчик в продукте — журнал событий
  сервера (смена фазы, сбои в консоли PyCharm); в тестах — проверки уведомлений.
- `Command(execute, can_execute)` — аналог `RelayCommand`. Доступность кнопок
  берётся из `state()["can"]`; недоступная команда через API даёт `409`.
- **Фаза эксперимента** (`Phase`): `idle`, `running`, `paused`, `completed`
  (достигнута `t_max`), `failed` (численный сбой). Причина завершения
  попадает в экспорт.
- Описание полей формы (`FIELDS`: подпись с единицами, тип, диапазон, «live»)
  живёт во ViewModel — View строит форму по `/api/schema`, поэтому клиентская
  и серверная проверки используют одни и те же границы.
- Разбор ввода: десятичная запятая, отказ от `NaN`/`inf`/`bool`/дробных целых.
  Проверяются **все** поля до применения; при ошибке не меняется ничего —
  ошибочный ввод никогда не подменяется значением по умолчанию.
- Поля с `live=True` (термостат, `t_max`, скорость анимации) применяются на
  лету, остальные пересоздают систему.
- **Бюджет вычислений**: за один кадр выполняется не больше
  `PAIR_STEP_BUDGET / N²` шагов — сервер не «зависает» на больших N.
- Подготовка данных: энергия на атом, дрейф энергии, единицы аргона,
  прореживание рядов до ~400 точек, усреднение g(r).
- Экспорт CSV/JSON с метаданными и загрузка параметров из JSON (строгая схема).

ViewModel тестируется без браузера и без сервера (`tests/test_viewmodel.py`).

## View (`lj_md/view`)

Сервер (`app.py`) — только маршрутизация, коды ответов и защитные лимиты
(тело ≤ 64 КБ, ≤ 32 сессий, по умолчанию только `127.0.0.1`). Контракт —
[API.md](API.md).

Клиент (`static/app.js`) реализует декларативную привязку:
`data-bind="путь.в.state"` и `data-command="имя"`. Собственное состояние View —
только визуальное: положение камеры в 3D и сообщение об ошибке связи
(«Сервер недоступен»). Экспорт PNG сцены и графиков выполняется на клиенте
(это отображение, а не данные); CSV/JSON формирует ViewModel.

## Почему веб и HTTP-слой

- Один язык (Python) для ядра и ViewModel; интерфейс открывается в любом
  браузере на macOS/Windows/Linux без установки GUI-фреймворков.
- HTTP-граница делает контракт View ↔ ViewModel явным и проверяемым
  (`docs/API.md` + контрактные тесты) и позволяет тестировать сквозной путь
  в настоящем браузере (`tests/e2e`).
- UI можно заменить (например, на PyQt) без изменения ядра и ViewModel —
  достаточно нового View, вызывающего те же команды и читающего `state()`.

## Тесты по слоям

| Слой | Файл | Что проверяется |
|---|---|---|
| Core | `tests/test_core.py` | законы сохранения, F = −∇U, PBC/стенки, t_max, откат при сбое |
| Core (эталоны) | `tests/test_verification.py` | аналитические эталоны, порядок схемы, давление двумя способами |
| ViewModel | `tests/test_viewmodel.py` | фазы, команды, валидация, экспорт/импорт, бюджет |
| View (HTTP) | `tests/test_web.py` | контракт state, коды ошибок, лимиты, сессии |
| End-to-end | `tests/e2e/test_browser.py` | браузер → HTTP → ViewModel → Core, PNG/CSV/JSON, «сервер недоступен» |
| Отчёт | `python -m verification` | полные эталонные проверки → `docs/VERIFICATION.md` |
