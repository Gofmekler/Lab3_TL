# Как работаем с репозиторием

## Ветки

- `main` — стабильная версия для защиты; напрямую в неё не пушим.
- `qa` — интеграционная ветка: сюда собирается готовое перед слиянием в `main`.
- Рабочие ветки — по роли и задаче: `core/verlet`, `ui/viewmodel`, `ui/charts`, `lead/api-docs`.

## Pull request

1. Ветка от актуального `main` (или `qa`), коммиты — **со своего аккаунта**
   (`git config user.name` / `user.email` — ваши, привязанные к GitHub).
2. PR в `qa` или `main`, заполнить шаблон (галочки роли и проверки).
3. CI (`tests`) должен быть зелёным: тесты на Linux, macOS, Windows.
4. Ревью: PR core и UI смотрит тимлид, PR тимлида — любой другой участник.
5. Порядок слияния по слоям — [docs/ROLES.md](docs/ROLES.md#порядок-работы-и-слияния).

## Определение «готово» (Definition of Done)

- код в своём слое и не нарушает направление зависимостей
  (`core` не импортирует ничего из `viewmodel`/`view`, ViewModel — Flask);
- есть тесты; для новой физики — по возможности эталонный случай
  с аналитическим ответом ([docs/VERIFICATION.md](docs/VERIFICATION.md));
- если менялся контракт `state()`/маршруты — обновлён [docs/API.md](docs/API.md);
- если менялось поведение для пользователя — обновлён `README.md`;
- `python -m pytest` проходит.

## Сообщения коммитов

Префикс роли и суть изменения: `Core: термостат Берендсена`,
`UI: экспорт JSON во ViewModel`, `Тимлид: контракт API`.

## Проверка перед PR

```bash
python -m pytest -q
python run.py        # приложение открывается, кнопки работают
```
