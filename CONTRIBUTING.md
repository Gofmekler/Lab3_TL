# Как вносить изменения

## Ветки

| Ветка | Назначение | Кто сливает |
|---|---|---|
| `main` | финальная версия для защиты; только через PR из `development` | тимлид |
| `development` | интеграция слоёв; только через PR | тимлид после review |
| `qa` | проверка интеграции перед `main` | тимлид |
| `feature/core-*`, `feature/ui-*`, `fix/*` | работа над задачей | автор открывает PR |

`main` и `development` защищены (настраивается в GitHub → *Settings → Branches →
Add branch protection rule*): обязательный PR, ≥ 1 approve, зелёный CI, запрет force-push.

## Порядок работы над задачей

1. Issue с описанием и критерием готовности.
2. Ветка от `development`: `feature/core-thermostat`, `feature/ui-png-export`…
3. Коммиты в стиле `core: …`, `ui: …`, `vm: …`, `docs: …`, `ci: …`, `fix: …`.
4. Локально: `ruff check .` и `python -m pytest`.
5. PR в `development` по шаблону; review от участника **другой** роли
   (core ↔ UI, тимлид — для интеграции).
6. Слияние только при зелёном CI и закрытом Definition of Done.

## Definition of Done

Задача считается выполненной, когда:

- [ ] код в своём слое: физика — только в `lj_md/core`, состояние и команды —
      в `lj_md/viewmodel`, отображение — в `lj_md/view` (зависимости только вниз);
- [ ] изменён контракт → обновлены `docs/API.md` и контрактные тесты `tests/test_web.py`;
- [ ] новая физика → тест с **независимым** эталоном (аналитика, закон сохранения,
      другой способ измерения) в `tests/` и, при необходимости, в `verification/`;
- [ ] ошибочный ввод даёт сообщение у поля, а не значение по умолчанию;
- [ ] `ruff check .` и `python -m pytest` проходят локально, CI зелёный;
- [ ] интерфейс проверен вручную (`python run.py`), для UI-изменений — скриншот в PR;
- [ ] README/docs соответствуют реальному поведению (без обещаний «на будущее»);
- [ ] review от участника другой роли получен, замечания закрыты.

## Перед защитой (тимлид)

- [ ] `python -m verification` — все проверки ✅, обновлённый `docs/VERIFICATION.md` закоммичен;
- [ ] `python scripts/make_screenshots.py` — актуальные скриншоты;
- [ ] финальный PR `development → main` с review всех участников;
- [ ] чистый clone → запуск по README на macOS и Windows.
